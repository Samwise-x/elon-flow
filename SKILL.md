# Elon Flow

Start from the desired observable outcome. Inspect the real artifact and applicable local skills before proposing changes. Distinguish hard constraints from inherited assumptions. Remove unnecessary requirements and steps before optimizing what remains. Deliver the smallest complete working capability.

Use `skills/simplification/SKILL.md` for complexity detection and `skills/architecture/SKILL.md` when module boundaries or ownership change. Record actual evidence, not imagined verification. Stop when the objective is met.
